The search hydration race is fixed and committed as `3e8cbcd fix: stabilize search input hydration`, on top of the WIP and S5 commits. Every check below ran on fresh production builds and passed. Nothing was pushed or deployed.

**1. Root cause.** The search box lives in the root layout and starts empty (`query = ""`), so the server HTML for `/s?k=headphones` shows an empty field. After the page loads, an effect copied the URL query into the field unconditionally, including on first load. Typing right after load went wrong in three ways:
- **Clicked in while empty, typed after the query appeared:** the query landed under the cursor and typing appended to it, giving `headphoneslaptop` (12/12).
- **Typed between page load and the query appearing:** the query overwrote the first keystroke, giving `headphonesaptop` (3/3).
- **Typed before the page's JavaScript loaded:** React keeps that text on screen but never reports it, so the effect replaced it with `headphones` (6/6).
